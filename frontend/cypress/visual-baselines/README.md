# Visual regression baselines

The versioned PNGs in `uat_capture_pages.spec.js/` are the approved screenshots
for the Cypress UAT capture spec. The UI automation workflow compares every
captured PNG with its baseline. Missing screenshots, new unbaselined screenshots,
dimension changes, and differences above the threshold fail the job.

Comparison uses Pixelmatch with a per-pixel threshold of `0.1`; a screenshot
fails when more than `0.1%` of its pixels differ. Any non-identical comparison
emits a `.diff.png` image to the `ui-ux-visual-diffs` Actions artifact, alongside
the actual capture in `ui-ux-screenshots`.

## Capture environment

- GitHub Actions runner: `ubuntu-24.04`
- Container: `cypress/included` pinned by image digest in the UI automation
  workflow (Debian 13, Node 24.15.0)
- Browser: Cypress 15.14.2 with bundled Electron 37.6.0
- Viewport requested by the spec: `1366 x 768`; Cypress 15.14.2 emits
  `1280 x 720` screenshot PNGs in this capture environment
- Screenshots are viewport captures; Cypress fixtures and API intercepts in the
  spec provide the page data

The pinned image supplies the browser, graphics libraries, and DejaVu Sans
font. Baselines should be generated by the workflow, not on a developer host
with a different font or graphics stack.

## Updating baselines

Baseline changes are never applied automatically. For an intentional visual
change:

1. Inspect the actual screenshots and every generated diff artifact from the
   workflow.
2. Copy the reviewed captures from `ui-ux-screenshots` into the matching
   baseline directory, including removals when a capture is intentionally
   retired.
3. Include baseline PNG changes with the UI change in the same pull request.
4. Obtain approval from the visual-baseline code owner and rerun the workflow.

Do not update a baseline merely to make a failing comparison pass. The reviewer
must verify that the image change is expected and that the post-update
comparison passes.
